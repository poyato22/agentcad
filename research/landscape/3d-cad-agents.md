# CAD agents can model parts, but nobody closes the print loop

Yes. Many people have built AI agent harnesses for mechanical CAD, and by late 2026 the space is crowded. Every major CAD tool now has at least one community MCP server. Autodesk (Fusion), PTC (Onshape) and McNeel (Rhino) ship official ones. The most-starred mechanical harness is **earthtojake/text-to-cad**, a build123d plugin for Claude Code, Codex and Cursor with about **22.9k stars**. It already chains a prompt through STEP, manufacturability checks and OrcaSlicer G-code to a Bambu printer. The winning design is the same everywhere. The agent writes code-as-model (build123d/CadQuery on the OCCT kernel, OpenSCAD, Zoo's KCL or FeatureScript). Deterministic tools then judge it: kernel validity, measured geometry deltas, wall thickness and interference, and FEA. Multi-view renders act as a coarse sanity check. The harness matters more than the model. Agents do well on simple printable parts, yet on 2026 engineering benchmarks frontier models meet only **20–30% of requirements**, and **58% of executable outputs** break at least one engineering rule. Fabrication is the weakest link. Agents can now slice and send jobs to printers, but no published system prints a part, measures it automatically, and revises the CAD from the measurement. Your installed Onshape FeatureScript MCP is a narrow tool: it writes custom features rather than doing general modeling. Pair it with a general Onshape server or a build123d harness. The open territory for a builder is the physical half of the loop.

## Every CAD app has an MCP server, but only a few let the agent check its work

The pattern blender-mcp started now covers the whole industry. An add-in runs inside the CAD app, a socket bridge connects it to an MCP server, and an `execute_code` escape hatch lets the agent run arbitrary API calls. Star counts track general popularity more than mechanical fitness. Blender's server (now **ahujasid/mcp-for-blender**, about **32k stars**) produces meshes, not exact solids or STEP ([GitHub](https://github.com/ahujasid/mcp-for-blender); [BuildCAD](https://buildcad.ai/guides/cad-mcp-servers)). For dimensioned parts, the B-rep servers are what count. **neka-nat/freecad-mcp** (about **3.0k stars**) returns screenshots after most tools and includes CalculiX FEM ([GitHub](https://github.com/neka-nat/freecad-mcp)). The smaller **blwfish/freecad-mcp** adds sketch-constraint inspection, wall-thickness and collision checks, and CNC G-code ([GitHub](https://github.com/blwfish/freecad-mcp)). **pzfreo/build123d-mcp** ("Give your AI CAD eyes") renders previews, measures geometry, gates on validity before export, and can edit features in imported STEP files. It self-reports that on the CADGenBench leaderboard it raised the same model's score from **0.360 to 0.457** and CAD validity from **88% to 100%** ([GitHub](https://github.com/pzfreo/build123d-mcp)).

The incumbents' official servers are narrower than their names suggest. Autodesk announced Fusion MCP servers in April 2026 and put a cloud Fusion Compute MCP into public beta on 2026-09-15 ([Autodesk](https://www.autodesk.com/products/fusion-360/blog/fusion-compute-mcp/)). Autodesk itself calls them "not yet reliable for complex models or full assemblies," and they are closed source ([BuildCAD](https://buildcad.ai/guides/cad-mcp-servers)). PTC announced its Onshape FeatureScript MCP Server on 2026-08-13 through Onshape Labs. It writes FeatureScript custom features and does not do general modeling ([PTC](https://www.ptc.com/en/news/2026/onshape-launches-featurescript-mcp-server)). Sources disagree on its status: BuildCAD calls it early access, while a competitor blog says it reached GA in August ([Leo AI blog](https://www.getleo.ai/blog/onshape-built-in-ai)). McNeel's official **mcneel/RhinoAI** includes a Rhino MCP server ([GitHub](https://github.com/mcneel/RhinoAI)). Dassault, Shapr3D and Inventor have no official server, though community SolidWorks servers exist; the largest, **vespo92/SolidworksMCP-TS**, warns that most tools are untested against a live SolidWorks ([GitHub](https://github.com/vespo92/SolidworksMCP-TS)).

For an Onshape user, the community servers fill the gap. **ReshefElisha/jarvis-onshape-mcp** (175 stars) is the most verification-heavy server in any CAD tool. It ships about 60 tools as a Claude Code plugin. Every mutation returns bounding-box, part-count and mass deltas. It also renders four-view shaded PNGs, compares them against a reference, and reads drawing dimensions with OCR to work around "Claude's vision downsampling" ([GitHub](https://github.com/ReshefElisha/jarvis-onshape-mcp)). **hedless/onshape-mcp** (156 stars) has broader modeling coverage: sketches, extrude, revolve, patterns, mated assemblies, interference checks and STEP/STL export. It cannot render images ([GitHub](https://github.com/hedless/onshape-mcp)).

| Server | Renders | Numeric feedback | Manufacturing/constraint checks |
|---|---|---|---|
| jarvis-onshape-mcp | 4-view PNG, reference compare, drawing OCR | per-feature bbox/mass/part deltas | regen hints, bbox interference |
| hedless/onshape-mcp | none | bbox, body details | interference |
| build123d-mcp | PNG/SVG | measure, topology, volume | validity gate, printability |
| RobertCoop/openscad-mcp | multi-view plus sections with scale bar | volume, cavities, bbox | interference, watertightness |
| NeonGlay/inventor-mcp | none | volume/topology delta per feature | transactions and rollback |
| neka-nat/freecad-mcp | screenshots | via code execution | CalculiX FEM |

Sources: [jarvis](https://github.com/ReshefElisha/jarvis-onshape-mcp), [hedless](https://github.com/hedless/onshape-mcp), [build123d-mcp](https://github.com/pzfreo/build123d-mcp), [openscad-mcp](https://github.com/RobertCoop/openscad-mcp), [inventor-mcp](https://github.com/NeonGlay/inventor-mcp), [BuildCAD](https://buildcad.ai/guides/cad-mcp-servers).

## Code-CAD plugins became the real harness, and numbers beat pictures

The biggest 2026 shift is the "skills plus local server" plugin. Instead of driving a GUI app, the coding agent writes build123d Python and calls local tools. **text-to-cad** is the clearest example. Its skills cover STEP-first CAD, off-the-shelf parts from step.parts, dimensioned drawings, robot URDF, SendCutSend checks, DfAM (wall thickness, overhangs, support volume, orientation), DFM rules with cited evidence, OrcaSlicer G-code, and Bambu printing ([GitHub](https://github.com/earthtojake/text-to-cad)). Standalone apps follow the same recipe. **Amagine3D** (about 6.3k stars) builds printable enclosures from the internal components outward. Its loop checks wall thickness, plate fit, interference and collisions along hinge and slider motion paths, then reads back the exported file to confirm it ([GitHub](https://github.com/amagine-ai/Amagine3D)). **CADAM** (about 5.3k stars) runs OpenSCAD in WebAssembly with Claude and exposes parametric sliders ([GitHub](https://github.com/Adam-CAD/CADAM)). Zoo's Design Studio is open source too ([GitHub](https://github.com/KittyCAD/modeling-app)).

Feedback design matters more than whether the agent can see the part. **Pan-Chera/Multi-Agent-CAD** reports a geometric-only loop hitting **99.3%** of 141 features for **$1.43 and 0.9M tokens**. The text-to-cad visual loop reached 93.6% for **$29.45 and 87M tokens** ([GitHub](https://github.com/Pan-Chera/Multi-Agent-CAD)). That is a competitor's self-reported benchmark comparing different workflows, so treat it as directional, not decisive. It agrees with other evidence, though. jarvis-onshape-mcp's author says the bottleneck "is not CAD execution, it's image interpretation" ([GitHub](https://github.com/ReshefElisha/jarvis-onshape-mcp)). The BenchCAD paper concludes that "textual instruction does the heavy lifting; the visual signal is at best a clarifier" ([arXiv](https://arxiv.org/html/2605.10865v1)). Practitioners on Hacker News report that text debug output often helps more than screenshots, and that Claude can "go deep in a wrong direction" while insisting a curve looks fine ([HN](https://news.ycombinator.com/item?id=47365299)).

The OpenSCAD-versus-build123d argument comes down to training data versus rigor. OpenSCAD has more training data and users report one-shotting threaded parts with BOSL2. It produces meshes only, and in Modelrift's summary, "CadQuery fails loudly and early… OpenSCAD fails silently and late" ([HN](https://news.ycombinator.com/item?id=48174405); [HN](https://news.ycombinator.com/item?id=49676577)). For mechanical work that has to reach STEP or other CAD tools, build123d/CadQuery or a native B-rep server is the better choice. CadQuery's maintainer published **jmwright/cadquery-llm-skill** because LLMs default to CSG thinking, misuse selectors and build in global coordinates ([GitHub](https://github.com/jmwright/cadquery-llm-skill)). Model choice still matters. In Kerrick Staley's OpenSCAD wall-mount test with a physics check, **Claude Opus 4.6 passed 30/30** trials, GPT-5.2 passed 26, and open-weight models mostly failed. Opus 4.1 had failed the same task entirely in a smaller run ([Blog](https://kerrickstaley.com/2026/02/22/can-frontier-llms-solve-cad-tasks)). Users still describe outputs as "95% there," with missing implicit constraints such as no room for nuts between a flange and fins ([HN](https://news.ycombinator.com/item?id=47970497)).

## Vendors ship copilots, and only a handful of products edit real models

Only a few commercial products run an agent that changes editable parametric geometry. **Zoo's Zookeeper** (launched 2026-02-05) writes and edits KCL, takes snapshots by default to check its own changes, and searches datasheets. Pricing runs from a free tier with $10/month of credit to unlimited use at $99/month ([Zoo](https://zoo.dev/blog/announcing-zookeeper)). An independent test had Zoo pass a cylinder but fail a gear and a manifold ([Xometry](https://xometry.pro/en/articles/text-to-cad-tools-test/)). **Adam** (YC W25) is the one most relevant to you. Onshape confirms its free open-beta App Store app edits Part Studio feature trees: it pulls hard-coded values into variables, renames features and merges redundant operations ([Onshape](https://www.onshape.com/en/blog/adam-ai-app-store-cad-co-pilot)). Adam also sells a developer platform with an MCP server ([adam.new](https://adam.new/)). **Leo AI** claims to generate full assemblies with feature trees across SolidWorks, Onshape, CATIA and Inventor, but "parts aren't mated automatically yet," and the evidence is CEO claims ([Engineering.com](https://www.engineering.com/leo-ai-can-now-generate-full-cad-assemblies/)). Earlier notes, based on Leo's own blog, described it as search and Q&A only, so its generation abilities are recent or overstated. Backflip (scan to parametric CAD in Fusion) and Spectral's SGS-1 (image or mesh to STEP) translate geometry rather than act as agents. They would work well as tools inside an agent ([mlq.ai](https://mlq.ai/news/backflip-ai-launches-scan-to-cad-tool-inside-autodesk-fusion/); [Pebblebed](https://pebblebed.com/portfolio/spectral)).

Among incumbents, Autodesk is furthest along. Autodesk Assistant became generally available in Fusion at AU 2026, alongside AutoTimeline, which turns imported geometry into editable parametric parts ([Autodesk News](https://adsknews.autodesk.com/en/news/autodesk-ai-design-manufacturing-au-2026/)). A standalone cross-product agent is expected in 2027 ([Architosh](https://architosh.com/2026/10/au2026-autodesk-shifts-ai-from-chatbots-to-agentic-ecosystems/)). Dassault's Mistral-based "Leo" companion demoed sketch-to-parametric-model plus FEA by prompt ([DEVELOP3D](https://develop3d.com/cad/new-solidworks-ai-agents-added-at-3dexperience-world/)). Onshape is the most open platform but the slowest on its own agents. Its shipped AI Advisor is a help assistant. Agents "added to projects like any other teammate," able to fix failing features and modify geometry, are still in development ([Onshape](https://www.onshape.com/en/blog/ai-artificial-intelligence-cloud-native-cad-pdm-platform)). No vendor publishes an independent success rate on real engineering parts.

## Benchmarks moved from shape similarity to requirements, and agents score 20–30%

The research splits into two lines. Specialist models trained to write CadQuery now reproduce benchmark shapes well. cadrille reports **92.2 IoU** on DeepCAD with 0% invalid outputs ([arXiv](https://arxiv.org/pdf/2505.22914)). That line still cannot build helical sweeps or involute gears ([BenchCAD](https://arxiv.org/pdf/2605.10865)). The second line puts frontier models in agent loops, and its 2026 benchmarks dropped Chamfer distance in favor of executable tests and engineering requirements. **CADEngBench** (MBZUAI, August 2026) tests 300 parts and 600 tasks with DFM checks, parameter perturbation and CalculiX FEA. The best validity was **58%** (Claude Sonnet 4.5), and the best requirement score was **30%** (Gemini 3 Flash). Edits involving joins, cuts or multiple bodies passed only 40–46% of the time, against 247 of 248 for isolated feature insertions. Pin-slot assembly joints scored **0%**, and tolerances were never evaluated ([arXiv](https://arxiv.org/html/2608.09296v1)). Son et al. gave Claude Code (Opus 4.7) and Codex (GPT-5.5) briefs requiring multi-part STEP assemblies checked by FEA. Neither produced a strict pass on the first attempt, and the best configuration met about **20%** of requirements ([arXiv](https://arxiv.org/abs/2605.17448)). Text2CAD-Bench warns that scores computed only over outputs that execute flatter models that fail often ([arXiv](https://arxiv.org/html/2605.18430v1)).

These papers give the clearest ranking of feedback signals. FEA has the strongest measured effect. In **Physics-in-the-Loop**, a LangGraph loop with a CadQuery writer, VLM geometry reviewer and torch-fem structural reviewer hit its target safety factor **59%** of the time with FEA feedback versus **22%** without (p = 0.0008), at $0.02–$0.20 per iteration ([arXiv](https://arxiv.org/html/2605.19717)). Rendered views give moderate gains. A blueprint schema plus a 21-view renderer raised Box-IoU from 0.44 to 0.59 ([arXiv](https://arxiv.org/abs/2605.17448)). Deterministic tools prevent hallucinated success. Without its MCP orientation tools, AgentsCAD's LLM invented rotation angles and claimed parts were overhang-free. Its VLM verifier also returned "inconclusive" on wall thickness because the renders were low resolution ([arXiv](https://arxiv.org/html/2607.02448v2)). Meshing, not solving, is where FEA breaks: 573 of 1,809 CADEngBench FEA failures came from meshing and boundary conditions ([arXiv](https://arxiv.org/html/2608.09296v1)). The consensus architecture is therefore a planner producing a blueprint, code in an OCCT kernel, deterministic gates, multi-view VLM review, then FEA. The agent may read the verdicts but never edit the thresholds.

## Printers are agent-controllable, but measurements never flow back into the CAD

The send-to-printer half is solved for hobbyists. text-to-cad goes from prompt to G-code to a Bambu printer inside one plugin ([GitHub](https://github.com/earthtojake/text-to-cad)). **DMontgomery40/bambu-printer-mcp** (233 stars) slices with BambuStudio or OrcaSlicer and prints over LAN with AMS support ([GitHub](https://github.com/DMontgomery40/bambu-printer-mcp)). Klipper and OctoEverywhere servers expose printer state and webcam snapshots ([OctoEverywhere/mcp](https://github.com/OctoEverywhere/mcp)). For consumers, Bambu's MakerWorld MakerLab pipes image-to-3D engines such as Meshy 6 into Bambu Studio ([smith3d](https://www.smith3d.com/bambu-lab-makerworld-unlock-ai-3d-model-generation-for-everyday-makers/)). The quality bar is low there: Bambu shut down two of its own AI tools on 2026-09-20 for missing "community expectations for model quality" ([3Druck](https://3druck.com/en/programs/makerworld-printmon-maker-and-ai-scanner-to-be-discontinued-by-bambu-lab-on-september-20-2026-30162323/)). Mesh generators make cosmetic parts, not dimensioned ones.

The measurement half barely exists. The closest research comes from Amir Barati Farimani's lab at CMU. **LLM-3D Print** watches each layer with a camera and has agents adjust temperature and flow mid-print, giving a **5.06× gain in peak load capacity**. It changes the process, never the geometry ([CMU](https://engineering.cmu.edu/news-events/news/2026/02/06-ai-saves-3d-prints.html)). **RocketSmith** had an LLM orchestrator design four printed high-power rockets. All four flew stably, with apogee at about 80% of prediction, but the paper does not show flight data driving a redesign ([arXiv](https://arxiv.org/abs/2606.00097)). **AgentsCAD** shows printing as the final step of its pipeline but reports no printed parts or mechanical tests ([arXiv](https://arxiv.org/html/2607.02448v2)). Boston University's **MAMA BEAR** proves the physical half works at scale. It ran more than **25,000 automated print-and-crush tests** and set a 75.2% energy-absorption record, but it uses Bayesian optimization over a fixed 11-parameter shell with no LLM ([arXiv](https://arxiv.org/pdf/2308.02315)). Duke's Text2Robot prints walking quadrupeds, with all revision done in simulation ([arXiv](https://arxiv.org/html/2406.19963v1)).

The best open-source attempt is **analogjedi/print-in-the-loop**. A YAML spec drives build123d CAD, and 84 to 365 automated checks run per design, covering interference, gear-mesh clearance and export round-trips. Seeded defects prove the checks fire. Parts print on a Bambu P2S, and "measurements from the real parts go back into the specs." Printing needs human approval, measurement is manual, and no measured fit results have been published yet. Its key line names the gap: "Software tolerances only show the model is self-consistent. Print fit is established only by measuring printed parts" ([GitHub](https://github.com/analogjedi/print-in-the-loop)). eschmitt88/agentic-3d-design has a similar verification ladder but no printer yet ([GitHub](https://github.com/eschmitt88/agentic-3d-design)).

## What to use today

Treat your official Onshape FeatureScript MCP as a specialist, not your main modeling tool. It is best at writing, testing and documenting custom features: parametric generators for things you make over and over, like gears, snap-fits, enclosure bosses or fastener patterns. Once written, those features become reusable tools for any agent ([PTC](https://www.ptc.com/en/news/2026/onshape-launches-featurescript-mcp-server)). The installed server also lists a `create_geometry` tool, so check whether it reaches beyond custom features before adding another server. Every call uses up your Onshape API allocation, and running out makes requests fail. Budget for that before running long render-and-revise loops.

For general modeling inside Onshape, add **jarvis-onshape-mcp**. Its per-mutation mass and bbox deltas and its four-view renders are exactly the feedback the research says matters. Reach for **hedless/onshape-mcp** if you need broader assembly and export coverage and can live without renders ([jarvis](https://github.com/ReshefElisha/jarvis-onshape-mcp); [hedless](https://github.com/hedless/onshape-mcp)). Install **Adam's** free Onshape app if you want to tidy and parameterize feature trees, even ones the agent built ([Onshape](https://www.onshape.com/en/blog/adam-ai-app-store-cad-co-pilot)).

For printable parts where you control the whole pipeline, the strongest stack today is local and open. Use **text-to-cad** as the Claude Code plugin for STEP, DfAM, slicing and Bambu printing, plus **build123d-mcp** for measurement and validity gating. Add **jmwright/cadquery-llm-skill**-style guidance so the model writes B-rep idioms instead of CSG habits ([text-to-cad](https://github.com/earthtojake/text-to-cad); [build123d-mcp](https://github.com/pzfreo/build123d-mcp); [cadquery-llm-skill](https://github.com/jmwright/cadquery-llm-skill)). Turn off telemetry in both text-to-cad and the Blender server. Use the best frontier model you can afford, since model generation alone swung one benchmark from 0% to 100% ([Blog](https://kerrickstaley.com/2026/02/22/can-frontier-llms-solve-cad-tasks)).

Whatever stack you pick, set it up the way the evidence supports. Have the agent build one feature at a time and return numeric deltas after each operation. Render orthographic multi-views only after major steps, because image loops are expensive. Write constraints as tests that run after the geometry is built. When working from photos, have a human review the extracted feature tree before the agent builds anything ([build123d-mcp](https://github.com/pzfreo/build123d-mcp); [MAC](https://github.com/Pan-Chera/Multi-Agent-CAD); [HN](https://news.ycombinator.com/item?id=49676577)). Add FEA, through freecad-mcp's CalculiX or torch-fem, only for load-bearing parts. That is where it measurably helps ([arXiv](https://arxiv.org/html/2605.19717)).

## Unclaimed gaps

The table ranks the gaps the notes found open, roughly from most to least feasible for a solo builder with a printer.

| Gap | Evidence it is open | Hardware needed |
|---|---|---|
| Autonomous print–measure–revise loop | No published LLM system revises geometry from measured fit or load; print-in-the-loop is human-gated and has no fit data ([GitHub](https://github.com/analogjedi/print-in-the-loop)) | Networked printer, USB camera, HX711 load cell |
| Tolerance/fit self-calibration | No study measures how LLM-chosen clearances fare once printed; CADEngBench skips tolerances ([arXiv](https://arxiv.org/html/2608.09296v1)) | Printer plus a coupon fixture or camera metrology |
| A physical benchmark | Every 2026 benchmark scores on renders, FEA or PyBullet; none on printed, measured parts ([arXiv](https://arxiv.org/html/2608.09296v1)) | Same as above; publishable |
| Agent-driven MAMA BEAR | The physical self-driving lab uses Bayesian optimization over fixed parameters; nobody has swapped in a topology-changing code-CAD agent ([BU](https://ar.bu.edu/2024/ai/self-driving-lab)) | Load cell crush or bend rig |
| A verification-first general Onshape agent | The official server writes FeatureScript only; Onshape's own editing agents are unreleased; jarvis was last pushed in April 2026 ([Onshape](https://www.onshape.com/en/blog/ai-artificial-intelligence-cloud-native-cad-pdm-platform); [jarvis](https://github.com/ReshefElisha/jarvis-onshape-mcp)) | None |
| Robust meshing/boundary-condition layer for agent FEA | Meshing and BCs cause a third of agent FEA failures ([arXiv](https://arxiv.org/html/2608.09296v1)) | None |
| Assemblies and mates | Pin-slot joints 0%, multi-body edits around 40%, Leo cannot mate parts ([arXiv](https://arxiv.org/html/2608.09296v1); [Engineering.com](https://www.engineering.com/leo-ai-can-now-generate-full-cad-assemblies/)) | None |
| Independent harness head-to-head | Every comparison of text-to-cad, MAC, build123d-mcp and Amagine3D is self-reported or from a competitor | None |

The first two gaps fit together and are the strongest pitch. Here is how the loop would work. The agent designs a mating pair (snap-fit, press-fit or gear pair) plus a clearance coupon set. It prints them over Bambu LAN or Klipper. A camera or a load-cell fixture measures fit, insertion force or deflection. The agent then updates both a per-printer clearance model and the CAD, under print-in-the-loop's rule that a failed check changes the geometry, never the threshold. Each iteration takes hours, not weeks, and every software piece is already open. One caution: some of these may already exist as unpublished hobby projects, and the Bambu P2S has documented CLI and LAN quirks ([GitHub](https://github.com/analogjedi/print-in-the-loop)). Search GitHub for the exact toolchain combination before committing.

There is a more Onshape-native angle as well. Build a FeatureScript library of fit-aware features whose clearance parameters come from your measured coupon data. The official MCP can then let any agent call "press-fit boss, calibrated for printer X" instead of guessing a tolerance. That combines the tool you already have with the gap nobody has filled.

## Conclusion

Design-side mechanical harnesses are becoming a commodity. Frontier models keep improving, vendors are building MCP servers into their products, and a 23k-star open plugin already does prompt to printer. A new modeling wrapper is a shrinking moat. The durable value sits in the judges: deterministic geometry checks, FEA that actually meshes, and, above all, measurements of real printed parts. Software tolerances only show the model agrees with itself, so the first harness to learn clearances from its own prints will produce parts that fit for reasons no render-based competitor can match.

Some uncertainty remains. Reddit and YouTube sentiment went unsurveyed. The CADGenBench leaderboard could not be retrieved. Industrial labs at Zoo, Autodesk or the startups may run print-measure-revise loops they have not published. The gap is unclaimed in public, not proven empty. A published result, even on simple snap-fits, would still be the first of its kind.
