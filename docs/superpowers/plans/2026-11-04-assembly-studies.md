# Plan 13 — Click-to-comment anywhere, faster Max, reliable websites, assembly studies (queued for after the 2026-11-04 usage reset)

| ID | Requirement |
|----|----|
| H1 | Click anywhere on the assembly to comment: in the default (select) tool a click on a part selects it AND offers an inline "Comment" bubble at the click point (no need to switch to the Comment tool first); clicks on empty space can also be commented (pinned to the world point). Pins carry instance + world point (E35 storage), go to the build's lead. |
| H2 | Faster Max: measure where time goes in a Max turn (effort max, plan→build→independent review sub-agent→revise). Make it faster without losing quality: run the review in parallel with remaining build work where possible, use a cheaper/faster model for mechanical sub-steps (classification, routing, renders summaries), skip the separate review when the change is trivial, stream the plan immediately, cache repeated renders/health checks, avoid duplicate re-reads of tool docs; show elapsed time per stage. Report before/after timings on 3 fixed prompts. |
| H3 | Websites that fail to open: many sites need JavaScript or block plain HTTP clients (Cloudflare challenges, 403s, empty bodies). Add a headless-browser fetch fallback (Playwright Chromium/WebKit already in the dev toolchain; bundle or install-on-demand with user consent) with the same SSRF/exfil guards and untrusted-text rules, a realistic UA, cookie-less, time and size limits; retry the plain fetch → headless → search-engine cache/snippet. Log which path succeeded; tests with a local JS-only page and a 403 page. |
| H4 | Assembly studies in the Studies page: pick the whole assembly (not one part) and run motion/system studies — e.g. "walk the dog" (gait trajectory → MuJoCo dynamics: joint torques vs actuators, stability, foot slip, ROM collisions, power), "launch the rocket" (rocket_flight with the assembly's mass/CG/geometry: apogee, stability, flutter, descent, payload g), "drop the egg capsule" (drop/impact), "run the mechanism" (gear/linkage sweep). Each runs as a background job with live progress, an immersive 3D playback of the assembly moving (with Section/X-ray), charts, pass/fail vs the spec, and peak loads handed to per-part FEM (dyn_to_fem). The studies agent proposes the right assembly study for the build type. |
| H5 | Model real-world reference objects accurately (e.g. "make a device for my Prusa MINI+"): a `reference_object` pipeline the agent must use whenever a build attaches to or fits an existing product. (1) Find authoritative geometry first: manufacturer CAD (STEP/STL on GitHub, Printables, GrabCAD, the maker's site — Prusa publishes MINI+ CAD), datasheets/manuals with dimensioned drawings, then measured community models; import STEP/STL directly as a read-only "reference" part (catalog import path, licence noted). (2) If no CAD exists: gather multiple images (official product photos from several views, manual figures) + every published dimension, build a dimension sheet with sources, and model it; then verify by rendering the model from the photo's viewpoint and comparing silhouettes/key points to the photo (image overlay sent to the agent with the image tools from F7), iterating until key dimensions and outline match within a stated tolerance. (3) Ask the user for 1–3 critical measurements (with a picture of where to measure) when the interface fit depends on them, and let the user drop their own photos (with a ruler/known object for scale). (4) Reference parts are marked as "reference" (not printed, not in the BOM, rendered ghosted/neutral), carry their source + confidence per dimension, and interface features (bolt holes, rails, bed size, clearances) are exposed as named datums the agent designs against. Tests: import a STEP reference; a dimension sheet with sources; silhouette-vs-photo comparison metric on a synthetic case; reference parts excluded from BOM/print. |
