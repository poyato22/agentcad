# Mises Mac App Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS desktop app (Tauri 2) that starts and supervises the Python core (`mises serve`) and gives the v1 core loop a UI: a 44px top bar, a left pane (parts, variables, run history), a Three.js viewer of the local mirror's GLB, and a full-height agent console (roster, step log, diffs, approval cards, command line, stop-all), plus a new-run dialog.

**Architecture:** Three layers, each as thin as possible. (1) A **Rust shell** (`app/src-tauri`) that only opens the window, spawns or attaches to the Python core, reads `server.json` for port and token, and hands them to the webview with one `invoke` command. Keychain, approvals, scope and budget all stay in the Python core. (2) A **web UI** (`app/src`, Preact + signals + Three.js, built with Vite) that talks straight to the core's localhost HTTP API and `/events` WebSocket. It keeps one store, treats Steps from `GET /runs/{id}/steps` as the source of truth, and uses WebSocket events only as "something changed" signals and for live text. (3) A **small core addition** (Task 1): read-only UI routes (`/status`, `/agents`, `/models`, `/parts`, `/parts/{id}/model.glb`), `POST /runs/cancel_all`, and CORS for the webview origin. Without these the UI can't list parts, load GLBs, fill the new-run dialog or stop all agents. Tests run the UI as a plain web app against a **fake core** (Node) that copies the real routes, auth and JSON. A contract test checks the fake against fixtures dumped from the real core.

**Tech Stack:** Tauri 2 (Rust stable; `ureq` for the health check, `serde`, `libc`), Node 22, TypeScript 5 (strict), Vite 6, Preact 10 + `@preact/signals`, Three.js r17x (`GLTFLoader`, `OrbitControls`), zod (validates server JSON at the boundary), `@fontsource/ibm-plex-mono` + `@fontsource/ibm-plex-sans-condensed` (bundled, no Google Fonts at runtime), Vitest + `@testing-library/preact` + jsdom, Playwright (Chromium), `tsx` + `ws` for the fake core. Python side: the existing core (FastAPI, pytest).

**UI framework: Preact + `@preact/signals`.** It is small (~4 KB), uses React-style JSX that most TS docs and examples cover (easiest for a Swift/Python developer new to TS), and signals update only the rows that changed, which matters during tool-call bursts. Solid would be just as fast but has fewer examples. Lit's class components suit this dense, list-heavy UI less well.

**Spec:** `docs/design/2026-10-24-mises-design.md` §5 (UX, §5.1 visual system, §5.2 screens, §5.3 interactions), §6 architecture, §9 packaging, §10 security. `research/harness/README.md` §8 (console lanes, event flow, keyboard rules). Look: `mockups/core-loop.html`, `mockups/terminal-core-loop.html`, `docs/overview/img/01-core-loop.png` (frame, panes, console only; see "Out of scope"). API: the **implemented** `core/src/mises/server/app.py`, `events.py`, `store.py`, `approvals.py`, `gate.py`, `cad/tools.py`, `runtime.py`. Plan 1 Task 8 is superseded where it differs.

## Global Constraints

- App lives in `app/` (Vite project root). Rust shell in `app/src-tauri/`. All npm commands run from `app/`. Python changes only in Task 1, under `core/`, run with `uv run` from `core/`.
- macOS only for now (Apple Silicon first, Intel builds are fine). Keep anything OS-specific in `app/src-tauri/src/platform.rs` so Windows can be added later. No Swift.
- **Colors (exact, as CSS custom properties in `src/styles/tokens.css`):** background `#0a0a0a`; panels `#111111` / `#161616` (header strip `#141414`, viewport `#0d0d0d`); lines `#242424` / `#333333`; text `#ececec` / `#9a9a9a` / `#5e5e5e`; blue `#3d8bff` / `#8dbaff` (tint `rgba(61,139,255,.10)`); green `#4fd18b`, amber `#f2b134`, red `#ff5a4a`.
- **Blue is used only** for: selected, being changed by an agent, or needs the human. **Green / amber / red are used only** for pass / warn / fail (amber also marks locked interfaces). Nothing else gets color.
- **Type:** IBM Plex Mono for all UI text (12px base). IBM Plex Sans Condensed for headings and pane titles. Both fonts are bundled locally.
- **Square corners everywhere:** `* { border-radius: 0 !important }` in `base.css`. A test checks computed `border-radius` is `0px` on buttons, cards and inputs.
- **No auto-numbered names** (design §5.1). The UI never shows names like `Extrude 1`, `Gusset1`, `Part Studio 1`, `#var1`, `GEOM-01` or `agent 2`. Rows read `Type · purpose`. Parts show as `Part · mount plate` (from `part_id`). Runs show as `designer · stiffen upright` (agent name plus the first words of the task). When two rows would read the same, add what differs (provider, model, start time like `14:02`), never a counter. All naming goes through `src/lib/names.ts`.
- Top bar is 44px with three zones: breadcrumb, mode tabs (Design · Studies · Sketch · Drawing · Print, with the active tab underlined in blue), and status lights. Studies, Sketch, Drawing and Print are shown **disabled** (`aria-disabled`, `#5e5e5e`, tooltip "later").
- **Approvals:** a card is approved only by an explicit click on its primary button, or by a key pressed while focus is inside that card. Never from a paste, never from the command line, never from a global shortcut, never from a synthetic event (`isTrusted === false`). There is no `/approve` command. **Never auto-approve.**
- **Global stop-all:** `⌘⇧.` plus a top-bar button. Both call `POST /runs/cancel_all`. It works from any focus, including text inputs.
- Talk to the core only on `127.0.0.1` with `Authorization: Bearer <token>`. The WebSocket uses `?token=`. The token comes from the Rust shell via `invoke("core_info")`, or in dev/test from `VITE_MISES_URL` / `VITE_MISES_TOKEN`. That fallback is compiled out of production builds. The token is never written to localStorage, logs or URLs other than the WS URL.
- **Untrusted text.** Agent output, tool inputs/outputs, Onshape names and file paths render as text only. `dangerouslySetInnerHTML` and `innerHTML` are banned by ESLint (`no-restricted-syntax`). No Markdown rendering in v1 (`white-space: pre-wrap`).
- CSP in `tauri.conf.json`: `default-src 'self'; connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; font-src 'self'`. The webview gets no Tauri `fs`, `shell` or `http` plugin capabilities, only `core:default` plus the two app commands.
- Server JSON is validated with zod at the client boundary. Unknown event types are ignored (logged at debug), never crash.
- At most one render per animation frame during event bursts. Store writes from events are batched with `requestAnimationFrame`.
- TS `strict: true`. No `any` in `src/api/**`.

## Review Focus

1. **Approval safety:** a paste, a held key, a synthetic key event, a key with focus outside the card, a stale `payload_hash` (409 `stale_version`) or a double click can never approve, or approve twice. A stale card refreshes in place. (Task 8 tests, Task 10 e2e.)
2. **Event stream gaps:** WS disconnect, core restart (new token: close 4401) or bus overflow (the core drops the oldest events at 1000) → the UI resyncs from `/runs`, `/approvals`, `/steps?after_id=` with no duplicate and no missing log rows. (Task 2, Task 10 tests.)
3. **Core lifecycle:** `uv` not on PATH in a Finder-launched app, a stale `server.json`, port in use, or the core crashing → a clear red status light, bounded restarts, and no orphan Python process after quit. (Task 3 tests.)
4. **Volume:** 500 tool calls in 2 s → one render per frame, folded into "▸ N more tool calls", and "follow" doesn't yank the view while the user has scrolled up. (Task 7 tests.)
5. **Visual rules:** no auto-numbered names anywhere, blue only where §5.1 allows, square corners, exact colors. Untrusted text is never rendered as HTML. (Task 2 tokens test, Task 7/10 e2e.)

## Real core API this plan builds on (from `core/src/mises/server/app.py`)

Existing routes (all need `Authorization: Bearer <token>`; errors are `{"error": ErrorCode, "message", "hint", "retryable"}` with the status map in `app.py`; 401 is `{"error":"unauthorized","message"}`; pydantic validation errors are 422 `{"detail":[...]}`):

| Route | Body / query | Returns |
|---|---|---|
| `GET /health` | | `{"ok": true}` |
| `POST /runs` | `{agent, prompt, model_ref?, edit_scope?=["*"], read_scope?=["*"]}` | `{"run_id"}` (404 unknown agent, 403 `denied` no API key, 400 bad model ref) |
| `POST /runs/external` | `{agent, provider, model, edit_scope?, read_scope?}` | `{"run_id"}` (not used by the v1 UI) |
| `GET /runs?limit=50` | | `AgentRun[]` |
| `GET /runs/{id}` | | `AgentRun` |
| `GET /runs/{id}/steps?after_id=0` | | `Step[]` (ascending id) |
| `POST /runs/{id}/message` | `{text}` | `{"ok":true}` (400 `invalid_input` "run is still working" / "driven by an external agent"; 404 if the run isn't live in this process) |
| `POST /runs/{id}/cancel` | | `{"ok":true}` |
| `GET /approvals?status=pending&run_id=` | | `Approval[]` (only `pending` supported) |
| `POST /approvals/{id}/decide` | `{payload_hash, approve: bool, edited_payload?}` | `Approval` (409 `stale_version` on hash mismatch; an already-decided approval is returned unchanged, so the first decision wins) |
| `POST /questions/{id}/answer` | `{text}` | `{"ok":true}` (404 if not open) |
| `WS /events?token=&run_id=` | | JSON `Event` per message; close 4401 = bad token |

`server.json` at `$MISES_HOME/server.json` (default `~/Library/Application Support/Mises/server.json`, mode 0600): `{"port": int, "token": str, "pid": int}`. `pid` is the **Python** process. It is removed on clean stop.

Event types actually published (`data` shapes): `run_started` `{agent, provider, model, parent_id, external?}` or `{resumed: true}` · `run_finished` `{status, stop_reason, error, final_text, external?}` · `tool_call` `{call_id, name, input}` · `tool_result` `{call_id, name, ok, summary}` or `{call_id, name, ok:false, error, message, hint, retryable}` · `approval_requested` = full `Approval` · `question_asked` `{question_id, question, options}` · `question_answered` `{question_id}` · `text_delta` `{text}` · `thought_delta` `{text}` (ACP) · `note` `{text}` · `plan` `{entries}` (ACP) · `usage` `{used, size, ...}` (ACP) · `diff` `{call_id, path}` (ACP) · `file_written` `{path, bytes}` (ACP) · `turn_retry` `{attempt}` · `compaction` `{summarized_messages, est_tokens_before, ...}`. There is **no** `approval_decided` and **no** per-step event. The UI refetches steps when it sees a `tool_call`/`tool_result`/`run_*`/`note`/`compaction` event.

Step payloads by origin: user/assistant `message` `{role, text, stop_reason?, tool_calls?:[{id,name}]}` · gate `tool_call` `{call_id, name, input}` · gate result steps (kind = `output.step_kind`: `tool_result`/`diff`/`measure`/`decision`/`error`…) `{call_id, name, output: ToolOutput}` · gate failure `error` `{call_id, name, error, message, hint, retryable}` · loop `error` `{stop_reason, error, message, hint, retryable}` · ACP `error` `{code, message}` · `decision` `{skipped_tools, reason}` · `compaction` `{...}`. `ToolOutput` = `{ok, summary, data, handles, warnings, step_kind}`. `mirror_part_set_vars` writes a `diff` step whose `output.data` = `{part_id, vars, delta:{volume_mm3, mass_g, bbox_size}, ...metrics}`. `mirror_export` returns `handles: ["<abs path>/model.glb"]`. The UI does not read handles from disk; it uses `GET /parts/{id}/model.glb` (Task 1).

## Spec conflicts and gaps found (resolve with the human; the plan's default choice is in brackets)

1. **Mockups and the overview PNG break the "no auto-numbered names" rule:** `Gusset1`, `Part Studio 1` (terminal mockup and `01-core-loop.png`), and agent names `GEOM-01`, `SIM-02`, `PRINT-03`, `MAT-04` (all mockups). [Follow the written rule: runs are labelled `agent · task`, never numbered.]
2. **The real API has no route for parts, GLB files, agents, models, Onshape status or stop-all**, and no CORS, so the webview's preflight would get 401. Plan 1 Task 8 didn't list them either. [Task 1 adds them in a new `ui_api.py` with a two-line hook in `app.py`.]
3. **`decide` is binary,** so Merge / Keep branch / Reject can't be told apart on the server. Design §5.3 implies Reject deletes the branch and Keep branch keeps it. [Keep branch = Reject = `approve:false`, labelled only in the UI. Propose that the core add `outcome: "merge"|"keep_branch"|"reject"` and branch deletion on reject.]
4. **Approvals carry no evidence links** (design §8 says badges link to a Step by id + hash). [The UI derives evidence from the run's measure/verify/sim_run/diff steps before the triggering tool_call. Propose an `evidence: [{step_id, hash}]` field on `Approval`.]
5. **No `approval_decided` or per-step events,** and the event bus silently drops the oldest events at 1000. [The UI refetches steps and approvals on any event and on reconnect. Steps are the source of truth.]
6. **Open questions aren't queryable** (no `GET /questions`), so a UI reload loses an open `ui_ask_user` card until it times out. [Accepted for v1. Propose `GET /questions`.]
7. **`server.json` `pid` is the Python pid,** while the app spawns `uv`. [The supervisor matches by file freshness + authenticated `/health`, not by pid, and kills the whole process group.]
8. **`mises serve` CLI isn't implemented yet** (`core/src/mises/cli/` is missing). [Tasks 2–9 don't need it. Tasks 10–11 wait on Plan 1 Task 11.]
9. **Rust is already installed** (Homebrew `rustc 1.99.1`), unlike what the brief said. [Use it. rustup only if it's missing.]
10. **The design's v1 core loop includes the sim split, env bar and printer dock;** this plan's agreed scope leaves them out. [Center = design viewer only. Tabs for later screens are disabled.]
